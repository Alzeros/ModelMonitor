# ModelMonitor

本地个人使用的模型输出效率监控网站。通过 OpenAI 兼容接口（`/v1/chat/completions`）自定义添加模型，平台按间隔主动发送流式测试请求，测量：

- **主指标 · 端到端吞吐 `avg_tps`** = `completion_tokens / 总耗时`，含思考 token 与首字等待（优先取官方 `usage`，缺失时按分块数估算并标记）
- **首字时间 TTFT**（请求发出到收到第一个可见输出分块）
- **可见输出速度 `tps`** = `可见 token / (流结束 − 首个可见分块)`，作为次要指标保留
- **总耗时**、可见 / 思考 token 数
- 错误分类：超时 / 认证失败 / 限流 / 服务端错误 / 网络错误 / 模型不存在等

## 技术栈

- 前端：React 19 + TypeScript + Vite + Tailwind CSS + shadcn/ui + Recharts
- 后端：Node.js (ESM) + Fastify + better-sqlite3，原生定时器调度
- 存储：SQLite 单文件 `data/monitor.db`（providers / models / probe_results 三张表；API Key 本地明文保存，勿提交/外传）

## 快速开始

```bash
npm install        # 根目录安装全部工作区依赖

npm run dev        # 开发模式：Fastify(3000) + Vite(22555，/api 已代理)，访问 http://127.0.0.1:22555

npm run build      # 构建前端到 apps/web/dist
npm start          # 生产模式：单进程托管前端 + API + 定时探测，访问 http://127.0.0.1:3000
```

## 使用说明

1. 「模型管理」→「添加供应商」：填名称、Base URL（如 `https://api.example.com/v1`）、API Key 与探测参数（间隔 / max_tokens / 超时），「测试连接」会请求 `{base_url}/models` 验证连通性
2. 在供应商卡片下「添加模型」：手动输入模型 ID，或「获取列表」勾选批量添加
3. 按供应商的间隔（默认 30 分钟）自动探测其下所有启用的模型：**同一供应商内按顺序串行探测**，相邻请求保持「模型间隔」（默认 5s，可配 0–60s），避免并发互相干扰；手动「立即探测」同样排队串行；供应商/模型均可单独停用
4. 「仪表盘」查看各模型最新速度与趋势图（1h/6h/24h/7d），每 30 秒自动刷新
5. 「探测记录」查看全部原始明细，支持按模型/状态/时间过滤

## 速度口径

- **主指标 `avg_tps = completion_tokens / 总耗时`**：含思考 token 与首字等待，衡量「从发出请求到收完内容」的端到端吞吐
- **次要指标 `tps = 可见 token 数 / (流结束时刻 − 首个可见分块时刻)`**：只反映可见输出的推送速率
- **为什么以 `avg_tps` 为主**：`tps` 排除了首字，一旦网关把响应缓冲后批量重放（思考型模型尤其常见），分母会塌缩成传输耗时，`tps` 被系统性放大数倍。对现有库实测：同一模型在「窗口 <1s」与「窗口 ≥1s」两组间，`tps` 中位数相差 **2.8–3.9 倍**，而 `avg_tps` 只差 1.01–1.20 倍
- **`avg_tps` 的已知局限**：分母含固定开销，**输出越短数字越低**（实测 <200 tok 约 50、4000–8000 tok 约 103 tok/s），跨模型比较需注意输出长度。卡片墙与对比图使用**区间中位数**并显示参与该中位数计算的**有效样本数**，进一步抗噪；没有区间数据时，卡片明确标注「最近一次 · 1 次有效样本」作为回退
- **有效性判定（`valid`）**：只评「端到端吞吐是否可信」——`avg_tps` 缺失或超过当前经验阈值 `1000 tok/s` 即提示「吞吐待复测」（该阈值不是通用物理上限，也不能据此确认缓存命中），不进入聚合。**可见输出窗口不参与该判定**，因此「思考结束后批量 flush」的样本仍被正常统计；这类样本的 `tps` 字段会单独置空，表示"可见输出速度不可信"
- 服务未返回 `usage.completion_tokens` 时按 SSE 分块数估算（记录标记「估算」）
- 部分服务不支持 `stream_options: include_usage`，后端遇到 400 会自动去掉该参数重试
- 思考型模型：prober 同时读 `delta.reasoning_content`，拆出「思考速度」与「可见输出速度」分别记录；模型可配思考强度（默认 / low / high / max），非默认时注入 `reasoning_effort`。思考阶段耗尽 max_tokens 会报 `no_content`，可调大 max_tokens 或降为 low
